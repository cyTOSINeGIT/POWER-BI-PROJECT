# Horizon Health Network Bed Capacity & Demand Analysis

## Overview

This Power BI project analyses hospital admissions, bed occupancy, capacity pressure and staffing indicators across Horizon Health Network. The dashboard consolidates operational data into an interactive view designed to support data-driven capacity planning and help move the organisation from reactive to proactive decision-making.

## Business Problem

Horizon Health Network faces uncertainty in bed availability due to fluctuating patient demand, varying occupancy levels and operational constraints. Admissions, bed occupancy and staffing information can be difficult to interpret when viewed separately, limiting early identification of capacity pressure.

## Objectives

* Analyse admission volumes and trends.
* Compare current and previous-year performance using Delta and YoY measures.
* Monitor staffed bed occupancy.
* Identify periods of increased bed pressure.
* Assess staffing gaps and their potential operational impact.
* Provide actionable insights to support capacity planning.

## Dashboard Features

The Power BI dashboard includes:

* **Total Admissions** – distinct count of admission records.
* **Admissions Trend** – visualises changes in admission activity over time.
* **Delta (Δ)** – shows the absolute change compared with the previous year.
* **YoY** – shows the percentage change compared with the previous year.
* **Staffed Bed Occupancy Rate** – measures occupied bed-days relative to staffed bed-days.
* **Bed Pressure** – highlights periods where available capacity becomes constrained.
* **Staffing Analysis** – supports assessment of workforce capacity relative to operational demand.
* **Interactive Filters** – allow users to explore different reporting periods and operational conditions.

## Key Business Insight

The analysis indicates that overall admissions remained relatively stable between 2024 and 2025, while bed utilisation and capacity constraints continued to create operational pressure. This suggests that pressure is not driven solely by increasing patient volumes, but also by the availability and management of staffed bed capacity.

## Business Solution

The dashboard provides a consolidated and repeatable analytical view that can help Horizon Health Network:

* Identify emerging capacity pressure earlier.
* Improve bed allocation and utilisation.
* Support proactive staffing decisions.
* Improve discharge and elective-planning coordination.
* Reduce reliance on fragmented manual reporting.
* Support better patient flow and operational efficiency.

## Tools & Technologies

* **Microsoft Power BI**
* **DAX**
* Data modelling
* Interactive dashboard design
* KPI and trend analysis

## Outcome

The project demonstrates how operational healthcare data can be transformed into decision-ready insight, enabling management to better understand demand, capacity and pressure across the hospital network.

# BRIT CONNECT Project Overview

This project focused on analysing network outage performance using Microsoft Power BI to provide a consolidated view of outage incidents, service-level performance, resolution times, and detection times across the network.

The analysis brought together outage incident, SLA performance, site, vendor, and root-cause information to examine key operational performance indicators and identify patterns affecting network reliability and service delivery.

The Power BI report was structured around four key performance areas: Overall Network Performance, SLA, Mean Time to Repair (MTTR), and Mean Time to Detect (MTTD).

## Network Outage Analysis

The project analysed network outage incidents to understand the scale and distribution of outages across different sites and operational categories.

The overview dashboard provided high-level KPIs and visualisations covering outage incidents, site performance, root causes, and service-level metrics. This created a consolidated view of network reliability and helped highlight areas requiring further investigation.

## SLA Performance

The analysis examined Service Level Agreement (SLA) performance across the network.

SLA performance was analysed by site, vendor, root-cause category, and other operational dimensions to identify variations in service performance and areas where SLA requirements may not have been consistently achieved.

## Mean Time to Repair (MTTR)

The project analysed Mean Time to Repair to understand how quickly network issues were resolved after an outage occurred.

MTTR performance was examined across sites, vendors, root-cause categories, and over time. The analysis helped provide visibility into differences in resolution performance and potential operational bottlenecks.

## Mean Time to Detect (MTTD)

The project also analysed Mean Time to Detect to evaluate how quickly network incidents were identified.

MTTD was examined by site type, root-cause category, severity level, vendor, and monthly trends. This provided insight into detection performance and helped identify areas where faster incident identification could improve overall network response.

## Power BI Dashboard

An interactive Power BI dashboard was developed to bring the analysis together into a clear reporting environment.

The dashboard included KPI cards, bar charts, column charts, line charts, area charts, funnel visualisations, and interactive navigation elements to allow users to explore network performance from different perspectives.

## Project Outcome

The project provided a structured view of network outage performance and operational efficiency, allowing key measures such as SLA, MTTR, and MTTD to be examined across different sites, vendors, root causes, severity levels, and time periods.

Overall, the project demonstrated practical skills in Power BI dashboard development, KPI analysis, operational performance reporting, data modelling, and interactive data visualisation, with a focus on improving visibility into network reliability and outage management.

# GreenTech Project Overview

This project focused on analysing production performance, downtime, batch activity, and operator performance using Microsoft Power BI.

The analysis combined production batch, product, downtime, and downtime-factor data to provide a consolidated view of manufacturing operations. The dashboard was designed to help identify the main causes of downtime, understand how downtime affected production duration, and compare operational performance across products and operators.

The Power BI report was organised into four main analytical areas: Downtime Factor Overview, Duration Analysis, Operator Scheduling, and Batches & Downtime Comparisons.

## Downtime Factor Analysis

The project analysed downtime factors across products, operators, error categories, and time periods. The dashboard examined the frequency of downtime factors and highlighted differences between operator-related and other error categories.

Downtime factors were compared by product and factor type, while trends over time were also visualised to identify periods with higher levels of downtime.

## Duration Analysis

The analysis compared planned batch duration with actual production duration across products.

Downtime hours were analysed by product, downtime factor, operator, and over time. The dashboard also examined downtime days according to error category, providing greater visibility into how operational issues affected production duration.

## Key measures included:

Number of batches
Number of downtime incidents
Total downtime days
Maximum downtime per batch
Planned batch duration
Actual batch duration
Total downtime hours

## Operator Scheduling

The project examined production scheduling and operator activity by analysing operators, batch dates, products, start times, and batch IDs.

An interactive operator view was created to allow individual operators and dates to be selected and examined. Operator-level downtime hours were also compared by error category, providing insight into operational performance and scheduling activity.

## Batch & Downtime Comparisons

The final analysis compared batch activity with downtime factors across operators and products.

The dashboard examined the number of batches associated with different operators and compared downtime-factor frequencies across products. This provided a clearer understanding of how production activity and downtime events were distributed across the operation.

## Power BI Dashboard

An interactive Power BI report was developed using KPI cards, bar charts, column charts, line charts, donut charts, tables, and slicers.

The dashboard allowed users to filter the analysis by product and start date, making it possible to investigate production and downtime performance from different operational perspectives.

## Project Outcome

The project provided a structured view of production performance and downtime, allowing key operational measures to be examined across products, batches, operators, downtime factors, error categories, and time periods.

Overall, the project demonstrated practical skills in Power BI dashboard development, data modelling, KPI analysis, production performance analysis, downtime analysis, operator analysis, interactive filtering, and business-focused data visualisation.
